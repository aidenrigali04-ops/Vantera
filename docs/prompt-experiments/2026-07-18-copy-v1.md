# Prompt experiment: copy-v1 — candidate system-prompt variants for the LinkedIn copy brains

Phase 2C, Task 4 (`docs/superpowers/plans/2026-07-18-enterprise-grade-brain-phase2c-quality-loop.md`).
This is a findings/proposal document, not a changelog of merged work. **Nothing in this document
has been applied to `LINKEDIN_SYSTEM` or `RESPOND_SYSTEM`** (`packages/agent-brains/src/copy/linkedin.ts`,
`packages/agent-brains/src/reply/respond.ts`) — the rig (`packages/evals/src/prompt-ab.ts`, `promptAB`)
and the tests proving it works (`prompt-ab.test.ts`) are the only things that shipped in this task's
commit. The candidate prompt variants below are **owner-runnable proposals**: read the gating section
first, then run each variant yourself when you have `ANTHROPIC_API_KEY` available.

## Why this pass is proposals-only, not executed numbers

This task was built by an agent without reliable access to a live `ANTHROPIC_API_KEY` (see the
task brief). `promptAB` itself is fully proven — `prompt-ab.test.ts` exercises it end-to-end against
`MockLanguageModelV3` (a rigged mock that clearly prefers the candidate draft over the baseline
proves the win path; a mock that always answers `"first"` regardless of content proves the
position-swap defense still resolves to ties through this rig, not just in the underlying
`pairwiseCompare`). What's genuinely missing is the LIVE run: drafting all 18 LinkedIn cases (and
optionally 18 respond cases) under each candidate, then judging each candidate draft against its
corpus case's `frozenDraft` baseline with a real model. That step needs the API key and costs real
money (each variant run drafts 18 cases once and judges each pair twice — the position swap — so
~18 draft calls + ~36 judge calls per variant; three variants ≈ 54 draft + 108 judge calls). It is
explicitly **not** run here. The methodology below is written so the owner (or a future session with
key access) can execute it verbatim and get numbers back in minutes.

## Gating — read this before treating any win-rate as a signal

1. **Owner-review-gated.** Even a variant that wins decisively is a PROPOSAL, never an auto-merge.
   `LINKEDIN_SYSTEM`/`RESPOND_SYSTEM` are registered, attributable production prompts
   (`registerPrompt`, stamped onto `SendRecipe.promptHash` at send time) — swapping one is a
   deliberate, reviewed change to what actually gets sent to real prospects, the same bar every
   other production prompt edit clears.
2. **Calibration-gated.** `PAIRWISE_NONINFERIORITY` and the judge's pairwise verdicts are explicitly
   **advisory, not trusted**, until the judge itself passes calibration: Cohen's kappa ≥ 0.7 against
   a real human rater (`docs/evals.md`'s calibration procedure, Phase 2C Task 1's
   `buildCalibrationPacket`/`scoreCalibration`). Until `EVALS_JUDGE_GATING=1` is set (which only
   happens after that κ ≥ 0.7 check passes), a pairwise win here means "the judge, which has not yet
   been shown to agree with a human," preferred the candidate — informative to look at, not a
   decision by itself. Run the calibration procedure before leaning on these numbers to actually
   change a production prompt.
3. **A judge preference is a proxy, not the metric that matters.** Per `docs/evals.md` and this
   phase's own plan, realized value ultimately gates on the funnel (replies, meetings booked), not
   the judge's specificity/them-focus/naturalness score. A winning pairwise report earns a real
   owner review and (if promoted) a period of live funnel-metric observation — it does not
   substitute for one.

## Methodology

Each variant below is a **full drop-in replacement** for `LINKEDIN_SYSTEM`'s text (or
`RESPOND_SYSTEM`'s, for the one respond variant), changing exactly one lever from the current
production prompt and leaving the shared `PROSPECT_ACCURACY_RULE`/`VOICE_RULES` blocks and the
closing seller-name line untouched — the same "one lever per experiment" discipline the production
`CopyStrategy` knobs already follow (`packages/agent-brains/src/copy/shared.ts`), applied here to a
wholesale system-prompt rewrite instead of a bounded knob, because a hook/them-focus/anti-slop
rewrite touches prose structure `CopyStrategy`'s existing knobs (`openWith`, `askStyle`,
`followupLength`, `openerAngle`) can't express.

To run a variant:

```bash
# 1. Save a variant's full text (below) to a file.
cat > /tmp/linkedin-variant-a.txt <<'EOF'
<paste the variant's full prompt text here>
EOF

# 2. Run the rig (needs ANTHROPIC_API_KEY; drafts all 18 linkedin corpus cases under the
#    candidate, pairwise-compares each against its frozenDraft baseline, prints the report).
pnpm --filter @vantera/evals evals:prompt-ab linkedin /tmp/linkedin-variant-a.txt
```

Or programmatically, if you want the `PairwiseReport` object directly (e.g. to script all three
variants in one pass, or to judge with a different/stronger model than the one drafting):

```ts
import { promptAB } from "./src/prompt-ab"; // from packages/evals
import { getModel } from "@vantera/ai";

const variantA = `...full prompt text...`;
const report = await promptAB(variantA, "linkedin"); // uses getModel() for both drafting AND judging
console.log(report); // { candidateWins, baselineWins, ties, winRate, nonInferior }
```

**Known limitation of the one-`model`-param API:** `promptAB`'s single `model` argument is used for
BOTH drafting the candidate copy AND judging the pairwise comparison. `runPairwise`'s own default
judge model is `JUDGE_MODEL_ID` (a stronger, different-family model — Opus — per `judge/pairwise.ts`'s
own design note that the judge should differ from the model being judged). If you want to draft with
the default model but judge with `JUDGE_MODEL_ID`, call the two halves manually instead of through
`promptAB`/the CLI: draft each case yourself under the candidate system via `generateObject`
(see `prompt-ab.ts`'s `draftLinkedinCandidate`/`draftRespondCandidate` for the exact prompt assembly),
then call `runPairwise(candidates, getModel(JUDGE_MODEL_ID))` directly. Kept as a follow-up rather
than widening `promptAB`'s signature, to stay inside this task's locked interface
(`promptAB(candidateSystem, brain, model?)`).

Record whatever win-rates you get back for each variant in this file (append a "## Results" section
with the `PairwiseReport` numbers and the date run) before treating any variant as a proposal to
formally review.

## Current production prompt (for reference — NOT a candidate, NOT the frozenDraft baseline)

`LINKEDIN_SYSTEM`, `packages/agent-brains/src/copy/linkedin.ts`. Reproduced here only so the deltas
below are legible; do not run this as a "candidate," and do not assume it produced the `frozenDraft`
baselines below — those are a separate, HAND-CURATED gold standard (`corpus.ts`), not a live sample
of this prompt's output. The live CI run of THIS prompt against those same frozen baselines already
wins pairwise winRate ≈ 0.653 (run 29628397074) — see the honest interpretation bar above the
Results table below before treating any candidate's win-rate as a decision signal.

```
You write LinkedIn outreach for a B2B seller: a connection note and one follow-up message (sent only after the prospect accepts).

Connection note, under 200 characters:
- Reference the prospect's trigger, work, or a genuine commonality. That's all. One short line lands better than two.
- NO pitch, no CTA, no links, no "I'd love to connect about our product". The only goal is an accepted request from a real-sounding peer.

Follow-up message: one or two short sentences, aim for about 120 characters and never exceed 180 (about 28 words). Shorter always wins. This is the FIRST real exchange, and buyers delete anything long or anything that opens with a pitch, so:
- Do NOT name the seller's company or product. Do NOT list features or describe what the seller does. Do NOT ask for a call, meeting, or demo. All of that comes later, after they engage.
- Shape: a brief thanks (3 to 6 words, not gushing), then ONE sharp observation about THEIR situation and ONE genuinely curious question about how they handle it today. The question is the whole CTA, so make it easy and interesting to answer.
- The "CTA goal" in the block only tells you where the conversation should eventually head. It must NOT appear as an ask in this message.
- If the prospect's location strongly implies a primary language other than English, writing in that language is welcome.

Getting their business right, for every message:
- When you mention what the prospect does, use THEIR OWN words from their title and "What they do". Never describe their business as if it were the seller's offer, never change their numbers, and never flip the direction of what they do (bringing in leads vs sending outreach, buyer vs seller, inbound vs outbound).
- If the "Value angle" seems to contradict their own title, trust their title. When you are not sure what they do, refer to their work only in the vaguest true terms, or not at all. Misdescribing their business ends the conversation, every time.

Voice, for every message:
- Write like you'd text a sharp colleague you respect. Plain, warm, specific. Use contractions (you're, that's, we've).
- Short and flowing. One thought per sentence. Cut every word that isn't pulling weight.
- NEVER use a dash of any kind as punctuation. No em-dashes, no hyphens between clauses. Use a comma, or start a new sentence. No semicolons, no bullet points, no numbered lists.
- Everyday words over business words. Say "use" not "utilize" or "leverage", "help" not "empower", "look into" not "delve". Never: streamline, elevate, seamless, game-changer, thrilled, kudos.
- No "Dear", no "Best regards", no signature, no generic flattery, at most one exclamation mark, minimal hedging.
- Read it back as if it were a text message. If it sounds like marketing, a template, or an assistant, rewrite it plainer and shorter.

If you ever reference the seller, use ONLY the "Seller company" value from the block, never any other brand name from the offer description.
```

## Variant A — sharper opening hook

**Lever:** the connection-note instruction currently allows "a genuine commonality" as a hook, which
in practice tends to produce safe, generic acknowledgment lines ("Saw you took on new clients, nice
growth!") that could plausibly be sent to five different prospects unchanged. This variant forces the
hook to be the single most specific, checkable fact available and explicitly bans generic-compliment
openers.

**Hypothesis:** a hook that fails the "could this line have gone to five other people" test reads as
templated even when it's factually accurate — tightening it to demand one unique, checkable detail
should raise the judge's specificity score and win more pairwise comparisons on the connection-note
half of the draft.

**Delta (only the "Connection note" bullets change):**

```
Connection note, under 200 characters:
- Open with the SINGLE most specific, checkable fact available about this prospect: their named trigger if the block has one, otherwise the sharpest concrete detail about their actual work or situation. Never a vague nod to "your work," "your industry," or "your growth."
- Never open with a generic acknowledgment a thousand other notes could have sent ("Great to connect", "Loved your profile", "Impressive background", "Nice to see your growth"). Test: could this exact line have been sent unchanged to five different prospects in five different industries? If yes, rewrite it around the one fact only this prospect has.
- NO pitch, no CTA, no links, no "I'd love to connect about our product". The only goal is an accepted request from a real-sounding peer.
```

**Run it:**

```bash
pnpm --filter @vantera/evals evals:prompt-ab linkedin /tmp/linkedin-variant-a.txt
```

## Variant B — harder them-focus

**Lever:** the follow-up message's shape opens with "a brief thanks" — even a short one, this puts
the SENDER'S action (connecting) as the first clause of the first real exchange. This variant forces
every follow-up to open on the prospect's own situation and demotes the thank-you to optional, at
most three words, no earlier than the second clause.

**Hypothesis:** opening on THEM instead of on "thanks for connecting" should raise the judge's
them-focus rating (grounded specificity from the first word, not after a pleasantry) without any
loss of warmth, since the thank-you is still allowed, just not first.

**Delta (only the "Shape" bullet + one new bullet change; everything else in the follow-up section
is unchanged):**

```
- Shape: open the very first clause on THEM — their trigger, their situation, or the specific pain named in the block. Never open on your own action ("Thanks for connecting", "Appreciate the connect", "Glad we connected"). A thank-you is optional and, if used at all, comes no earlier than the second clause, three words or fewer, never gushing. Follow with ONE genuinely curious question about how they handle their situation today. The question is the whole CTA, so make it easy and interesting to answer.
- Every sentence in this message should be checkable against THIS prospect's own facts in the block. If a sentence would still make sense with the prospect's name and company swapped for someone else's, cut it or sharpen it until it wouldn't.
```

**Run it:**

```bash
pnpm --filter @vantera/evals evals:prompt-ab linkedin /tmp/linkedin-variant-b.txt
```

## Variant C — tighter anti-slop

**Lever:** `VOICE_RULES` already bans a short list of business-jargon words (streamline, elevate,
seamless, game-changer, thrilled, kudos) but doesn't touch the far more common LLM-outreach clichés
("I noticed", "I wanted to reach out because", "I came across", "it caught my eye"). This variant
adds an explicit banned-phrase list for both the connection note and follow-up, plus a hard
specificity requirement (at least one concrete, block-sourced detail, never a generic
true-of-any-company-in-the-vertical line).

**Hypothesis:** these specific phrases are disproportionately common in AI-generated outreach and
disproportionately trigger "this is a bot" pattern-matching in a human reader; banning them by name
(the way `VOICE_RULES` already bans specific jargon words) should be a cheap naturalness win, and the
specificity requirement should reduce cases where the model reaches for a generic industry statement
when the block doesn't give it much to work with.

**Delta (a new paragraph inserted right after the follow-up-message bullets, before "Getting their
business right"):**

```
Banned outreach clichés — do not use any of these, or a close paraphrase, in the connection note or the follow-up: "I noticed", "I saw that you", "I wanted to reach out", "I came across", "it caught my eye", "I hope this finds you well", "I'll keep this short", "quick question", "excited to connect", "reaching out because", "wanted to connect because". If a sentence needs one of these to hold together, delete it and state the underlying observation directly instead.

Every message must include at least one concrete, specific detail drawn directly from the block (a named trigger, a named pain point, or a real number from Proof if one is offered) — never a generic statement that would be true of any company in that vertical. If the block genuinely has nothing specific to offer for this prospect, say less rather than filling the gap with a generic line.
```

**Run it:**

```bash
pnpm --filter @vantera/evals evals:prompt-ab linkedin /tmp/linkedin-variant-c.txt
```

## Variant D (optional, respond brain) — harder them-focus in reply mode

**Lever:** `RESPOND_SYSTEM` already bans acknowledgment preambles ("Fair enough", "Great question",
etc.) but the neutral/ambiguous branch of reply mode still allows an opening clause about the
sender's own next move. This mirrors Variant B's lever for the ongoing-conversation brain: the first
clause of every reply should reference something the prospect actually said or did.

**Hypothesis:** same reasoning as Variant B, applied mid-thread instead of at first touch — should
lift them-focus without changing which of the five reply-mode branches (small talk / question /
objection / buying signal / neutral) gets selected.

**Delta (one new bullet added to the "Rules for every message" list, after the acknowledgment-preamble
bullet):**

```
- The first clause of every reply must reference something the prospect actually said or did in the thread above — a word they used, a detail they gave, the specific thing they asked. Never open a reply with a statement about what you (the seller) are about to do or say.
```

**Run it:**

```bash
pnpm --filter @vantera/evals evals:prompt-ab respond /tmp/respond-variant-d.txt
```
